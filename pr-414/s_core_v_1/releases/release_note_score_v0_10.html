📋 Overview#

This document provides an overview of the changes, improvements, and bug fixes included in the software platform release version v0.10.0 as compared to the previous platform release (v0.9.0).

📜 Disclaimer#

This release note does not “release for production”, as it does not come with a safety argumentation and a performed safety assessment. The work products compiled in the safety package are created with care according to a process satisfying standards, but the project, being a non-profit and open source organization, can not take over any liability for its content.

🔄 Changes to the Platform#

✨ New Features#

Module Tests in the Module Workspace (DR-008)#

Each integrated software module now runs its own unit tests and coverage in its own Bazel workspace, against the dependency versions resolved by the reference integration, with one CI job per module. The test arguments of each module are kept in known_good.json (metadata.test_args), the shared build settings in bazel_common/unified.bazelrc. Locally: python3 scripts/module_tests.py run <module> (PR #398).

Shared Image Packaging#

The QNX images are built with score_rules_imagefs 0.1.0. Application files and configuration that both QNX images and the Linux image use are defined once in //images/common/apps, //images/qnx_common/build and //images/qnx_common/configs (PR #349, PR #389).

SBOM Generation#

Added generation of a Software Bill of Materials for the product dependencies (SPDX and CycloneDX) and for the build tools (SPDX), see the “Software Bill of Materials” section of the README (PR #304).

Module Integration Tests#

The integration tests of Lifecycle, Logging and Persistency run in the reference integration, and their results are linked to the requirements in the verification reports (PR #385, PR #387). The new infrastructure module Tools provides the pytest setup of the Persistency tests (PR #388).

Documentation and Verification Reports#

  • The documentation of the Time module is part of the integrated documentation (PR #348).

  • The module verification reports of Logging and Lifecycle are linked from the verification report overview (PR #367, PR #373).

  • The Unit Tests and Coverage summaries are nested under the Platform Verification Report (PR #358).

💥 Breaking Changes#

Reference Integration: Resolved-Dependency Override Removed#

The resolved-dependency override introduced in v0.9 (scripts/known_good/resolved_dependencies.py and scripts/known_good/module_patches.py) and the generated rust_coverage/BUILD were removed; module tests no longer run inside the reference integration workspace (PR #398). Action required: run module tests with scripts/module_tests.py and keep their test arguments in known_good.json (metadata.test_args).

Baselibs#

Baselibs is integrated at a commit after v0.2.14 and contains breaking changes of v0.2.13 and v0.2.14 (see the Baselibs release notes):

  • score/datetime_converter was removed (PR #471). Use POSIX or C library time APIs instead.

  • The unused score/os libraries cpuid, file_stream and make_dev were removed (PR #535).

  • The deprecated //src Bazel aliases and the string and atomic shims in //score/memory were removed (PR #598). Use the replacement targets.

  • score::flatbuffers::LoadBuffer now takes score::cpp::pmr::vector<uint8_t> instead of std::pmr::vector<uint8_t> (PR #603).

These are public APIs of Baselibs; the configuration of the reference integration does not use them. Action required: adapt own code that uses them.
