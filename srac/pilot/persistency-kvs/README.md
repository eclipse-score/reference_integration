# Persistency KVS SRAC pilot

This pilot applies the draft SRAC assertion to a real SPDX 2.3 product SBOM generated by the reference integration's
official `//:sbom` target. The checked-in input came from the successful Linux workflow on the exact upstream base commit of
this pull request. See `provenance.json` for its workflow URL, commit and SHA-256 digest.

The SBOM includes the Persistency module because both the C++ and Rust integration-test targets depend on KVS. The current
`sbom-tool` output identifies that module as `pkg:github/eclipse-score/score_persistency@unknown`. The assertion retains the
canonical repository and pinned commit. Matching therefore also requires `known_good.json`; the tool only accepts the
`unknown` SBOM entry when its module name, repository and pinned hash resolve consistently.

This proves a deterministic module-level join. It does not make the draft assertion authoritative, assign KVS a safety
classification or modify the source SBOM.

## Retrieve the exact input SBOM

The byte-identical baseline can be downloaded while the GitHub Actions artifact is retained:

```bash
gh run download 36102870402 \
  --repo eclipse-score/reference_integration \
  --name sbom-spdx \
  --dir srac/pilot/persistency-kvs/input
sha256sum srac/pilot/persistency-kvs/input/sbom.spdx.json
```

Rename the downloaded file to `reference-integration.spdx.json`. Its expected SHA-256 is
`e147f5db23d35c97c8c779c217d6edb9977d01cddf7683e2c46d45cf09737243`.

## Regenerate an equivalent SBOM

On the supported Linux build environment, from the repository root:

```bash
bazel build --lockfile_mode=error --config=linux-x86_64 //:sbom
cp bazel-bin/sbom.spdx.json srac/pilot/persistency-kvs/input/reference-integration.spdx.json
sha256sum srac/pilot/persistency-kvs/input/reference-integration.spdx.json
```

The checked-in baseline was generated by workflow run `36102870402` at commit
`c4084156ccf7df963b7499fe5c2f67764496e8ae`. A regenerated SBOM has an equivalent component graph but may not be byte-identical
because `sbom-tool` records the generation timestamp.

## Apply the sidecar

```bash
python -m srac.tools.enrich_sbom \
  --assertion srac/examples/persistency-kvs.srac.json \
  --sbom srac/pilot/persistency-kvs/input/reference-integration.spdx.json \
  --known-good known_good.json \
  --output srac/pilot/persistency-kvs/output/persistency-kvs.srac-report.json
```

Expected result:

```text
matchStatus: matched
matched identifier: SPDXRef-score-persistency-unknown
binding strategy: score-known-good
known-good module: score_persistency
known-good hash: 9ae529ba9f413976ff5c9948c6490afa51bbfdc3
```

Omitting `--known-good`, changing its Persistency hash, or changing the assertion version produces `matchStatus: unmatched`
and a non-zero command exit. This prevents an `unknown` SBOM version from being accepted on name alone.
