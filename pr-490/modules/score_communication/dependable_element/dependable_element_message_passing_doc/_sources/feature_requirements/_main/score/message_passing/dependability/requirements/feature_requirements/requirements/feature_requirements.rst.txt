Feature Requirements
====================
.. requirement:definition:: MessagePassing.ServerInterface

   The message passing component shall provide a server interface that registers connection handlers and processes incoming requests.

.. requirement:definition:: MessagePassing.ClientInterface

   The message passing component shall provide a client interface that establishes and maintains a connection to a server, exposing its lifecycle state, the reason for its termination, and a callback invoked on every state change.

.. requirement:definition:: MessagePassing.OSIndependentAPI

   The message passing component shall provide an OS-independent API for OS-native IPC mechanisms.

.. requirement:definition:: MessagePassing.QMImplementationOnNonQnxOS

   The message passing component shall provide a QM-quality implementation of its API on host operating systems other than QNX, to support development, evaluation, testing, and QM deployment off the ASIL B certified target.

.. requirement:definition:: MessagePassing.SafetyCertifiedTransportMechanism

   The implementation under QNX shall use a safety-certified transport mechanism.

.. requirement:definition:: MessagePassing.PointToPointConnections

   The message passing component shall support only point-to-point (1:1) connections between communication endpoints. N:M connections are explicitly excluded.

.. requirement:definition:: MessagePassing.SynchronousUnidirectionalCommunication

   The communication shall support client-initiated one-way message sending (Send) on a given connection, where the send call is allowed to hand the message directly to the underlying OS transport call, which may block the calling thread, depending on client configuration and whether a reply is currently pending on the same connection.

.. requirement:definition:: MessagePassing.SynchronousBidirectionalCommunication

   The communication shall support synchronous bidirectional request-response communication on a given connection. The send call blocks until a reply from the receiver has been received (SendWaitReply).

.. requirement:definition:: MessagePassing.AsynchronousUnidirectionalCommunication

   The communication shall support client-initiated one-way message sending (Send) on a given connection, where the send call enqueues the message for asynchronous delivery by the background transport and returns after local acceptance, whenever client configuration or a reply currently pending on the same connection requires it. No guarantee is provided that an enqueued message is delivered to or processed by the receiver.

.. requirement:definition:: MessagePassing.AsynchronousServerNotification

   The message passing component shall allow a server to send a one-way notification message to a connected client (Notify), unconditionally asynchronously: the call returns after the message has been accepted by the local message passing layer, without blocking on the client's receipt or processing of the notification.

.. requirement:definition:: MessagePassing.SingletonFreeImplementation

   The Message Passing library design shall not use any singletons.

.. requirement:definition:: MessagePassing.AllowsBoundedMonotonicMemoryAllocation

   The Message Passing library design shall allow bounded monotonic memory allocation.

.. requirement:definition:: MessagePassing.AllowsResourceMockInjectionForTesting

   The Message Passing library design shall allow resource mock injection for testing.

.. requirement:definition:: MessagePassing.ClientIdentificationForAccessControl

   The message passing component shall provide the server-side application with the OS-provided identity of the client of each Server Connection, to support server-side client identification and access control decisions.
