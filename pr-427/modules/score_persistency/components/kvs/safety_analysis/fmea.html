Generic Document

Failure modes at the component interfaces are analysed in Persistency FMEA (doc__persistency_fmea). This FMEA applies the fault models of FMEA Fault Models (gd_guidl__fault_models) to the mechanisms specified in KVS Requirements (doc__kvs_requirements). The scope is defined in Persistency Safety Plan (doc__persistency_safety_plan) (tailoring).

FMEA#

Flush is interrupted
status: valid
failure_effect: Data and hash file are written incompletely.
failure_root_cause: Reset or power loss during the flush, write error of the storage medium.
fault_id: MF_01_05
safety_relevant: yes
sufficient: yes
version: 1
mitigated_by: comp_req__kvs__atomic_store, comp_req__kvs__corruption_detect_open, comp_req__kvs__pers_data_csum, comp_req__kvs__recovery_snapshot_restore, comp_req__kvs__reset_resistant_write
violates: comp_arc_sta__persistency_kvs__sv

The previous state is kept until the flush is complete; an incomplete flush is detected at the next open.

Implementation: the previous state is only kept by the snapshot rotation, so with a maximum snapshot count of 0 Reset Resistant Write (comp_req__kvs__reset_resistant_write) is not met.

Corrupted storage at open, reload or snapshot restore
status: valid
failure_effect: Corrupted or inconsistent data is loaded into the in-memory cache.
failure_root_cause: Interrupted flush, fault of the storage medium, data or hash file missing or modified by another software element.
fault_id: MF_01_05
safety_relevant: yes
sufficient: yes
version: 1
mitigated_by: comp_req__kvs__corruption_detect_open, comp_req__kvs__key_uniqueness, comp_req__kvs__open_need_kvs_behavior, comp_req__kvs__permission_err_hndl, comp_req__kvs__pers_data_csum_vrfy
violates: comp_arc_sta__persistency_kvs__sv

Applies to every load: open, Discard Pending Changes (comp_req__kvs__discard_pending_changes_api) and snapshot restore.

Implementation (Rust): a missing hash file is reported as FileNotFound, so with Optional the instance is opened with empty storage although the data file exists.

comp_saf_fmea__kvs__default_corrupt
Component FMEA (Failure Mode and Effects Analysis)
Flush does not write changed data
status: valid
failure_effect: Flush returns without error, but the changes are lost at the next reset.
failure_root_cause: The change detection of :need:`comp_req__kvs__write_amplification` misses a change.
fault_id: MF_01_06
safety_relevant: yes
sufficient: no
version: 1
mitigated_by: comp_req__kvs__explicit_flush, comp_req__kvs__write_amplification
violates: comp_arc_sta__persistency_kvs__sv

A missed change is not detected by the checksum, which covers the written data only. Not sufficient: it is not specified that every modifying operation marks the data as changed.

Implementation: no change detection, flush always writes.
comp_saf_fmea__kvs__flush_skipped
Component FMEA (Failure Mode and Effects Analysis)
Constraint boundary is violated
status: valid
failure_effect: A key, the snapshots or the persisted data exceed the configured limits, or an invalid snapshot slot is used.
failure_root_cause: The application passes an invalid key or snapshot slot index, or stores more data than configured.
fault_id: CO_01_02
safety_relevant: yes
sufficient: no
version: 1
mitigated_by: comp_req__kvs__constraints, comp_req__kvs__key_length, comp_req__kvs__key_naming, comp_req__kvs__no_dynamic_memory, comp_req__kvs__snapshot_max_num_cfg, comp_req__kvs__snapshot_remove_api, comp_req__kvs__snapshot_restore_api, comp_req__kvs__snapshot_slot_index_vali
violates: comp_arc_sta__persistency_kvs__sv

Not sufficient: Snapshot Slot Index Validation (comp_req__kvs__snapshot_slot_index_vali) checks the fixed range of Snapshot Slot Indexing (comp_req__kvs__snapshot_id_api), not the configured maximum of Maximum Number of Snapshots (comp_req__kvs__snapshot_max_num_cfg). A snapshot above the configured maximum exceeds the configured storage.

Implementation: Rust does not validate keys; the snapshot create, remove and slot query API is missing.
